## 🎯 Цель проекта
Разработать интерактивное дашборд-решение для менеджмента и логистов сервиса, позволяющее:
* Мониторить операционную динамику и временные тренды.
* Выявлять инфраструктурные «узкие места» и перераспределять парк велосипедов.
* Разделять пользовательские сценарии (commuters vs tourists) для повышения конверсии подписок.

## 🛠 Архитектура и Ключевые Блоки Отчета

### 1. Операционные тренды `[A]`
* **Динамика объемов (MoM, QoQ, YoY):** Отслеживание приростов и сезонности поездок.
* **Средний дневной объем:** Расчет регулярного трафика через динамические DAX-меры.
* **Матрица загрузки (Часы пик):** Тепловая карта «День недели × Час суток», подсвечивающая пиковые интервалы **08:00–09:00** и **17:00–18:00**.
* **Региональный срез:** Выделение и анализ пиковых месяцев нагрузки в регионе **San Jose**.

### 2. География и Инфраструктура `[B, C]`
* **Гео-карта станций:** Точное отображение локаций по широте и долготе (`Latitude` / `Longitude`) с цветовой индикацией средней длительности поездки.
* **Сквозная детализация (Drillthrough):** Переход к карточке конкретной станции по правому клику на точку.
* **Оптимизация сети (Underutilized Stations):** Автоматический реестр недоиспользуемых станций (**< 5 поездок/день**) для оценки их целесообразности и релокации.
* **Топ-маршруты:** Рейтинг наибоее популярных связок `Start Station ➔ End Station`.

### 3. Сегментация пользователей `[D]`
* **Subscriber vs Customer:** 
  * *Subscribers (Подписчики):* Генерируют **80%+** поездок, короткие утилитарные поездки в будни (10–12 мин).
  * *Customers (Разовые клиенты):* Длительные рекреационные поездки в выходные дни (25–30+ мин).
* **Демографический профиль:** Анализ половозрастной структуры пользователей.
